
# Roadmap for 2026-11-26: backend core (about 50%) plus Swagger hand-off

## Goal
By the end of today, the backend covers the core money features and serves full
OpenAPI/Swagger docs, so a friend can build the Flutter app against it without asking us
questions.

## How we work today (agreed with the user)
- Claude writes all backend code and tests. No `USER WRITES` files.
- The user approves this roadmap once. Each step still gets a short `prompts/NNN-*.md`
  (contract and decisions) and a short `docs/learn/NNN-*.md`, written as the step is built.
- One branch per step, `feature/<name>`, cut from the previous step's branch, because PRs
  merge later and each step builds on the one before. One commit per step, pushed, PR text
  copied to the clipboard.
- Every step must pass `./mvnw -q verify` before it is committed.
- No Flutter today. The friend builds it.

## Key decisions (apply to every step)
- **springdoc-openapi 3.x** (the line for Spring Boot 4). Check the exact version against
  its docs before adding it. Swagger UI is public in `dev` and turned off by default in
  other profiles (`springdoc.api-docs.enabled=false`), so we don't publish our API map in prod.
- **Money**: `BigDecimal` with `NUMERIC(19,4)`, and a **string** in JSON (`"1250.50"`).
  Documented in Swagger as `type: string, format: decimal`.
- **Ledger**: a transaction row is the movement. `accounts.current_balance` is a cache,
  changed only with `UPDATE accounts SET current_balance = current_balance + :delta`
  inside the same `@Transactional` as the insert. There is a rebuild query for checks.
- **Kinds stored now**: INCOME, EXPENSE, TRANSFER, OPENING_BALANCE, ADJUSTMENT (and LEND,
  BORROW and the repayment kinds in 013). Reports filter `kind IN ('INCOME','EXPENSE')`
  through one shared constant.
- **Ownership**: every query uses `user_id = currentUser.id()`. Another user's id returns
  404. Each feature has an A-vs-B integration test.
- **Pagination**: lists use `?limit=&cursor=`; the response is
  `{ items: [...], nextCursor: "..." | null }`. Small lists (accounts, categories) return a
  full array.
- **Errors**: new stable codes per feature (for example `ACCOUNT_NOT_FOUND`,
  `CATEGORY_IN_USE`, `IDEMPOTENCY_KEY_REUSED`), all Problem Details.

## Deferred (not today, noted for later)
- Email verification and password reset (these need an email provider).
- Rate limiting and caching (these need Redis; they come in one Redis step later).
- Budgets, recurring, calendar, search, goals, attachments, exports, notifications, AI.

## Checks per step
1. `./mvnw -q verify` passes (Testcontainers Postgres).
2. `./mvnw spring-boot:run -Dspring-boot.run.profiles=dev` starts, and Flyway applies the new migration.
3. The new endpoints show up in Swagger UI and work through "Try it out".
